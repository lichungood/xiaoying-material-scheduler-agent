# 04 AI 使用范围、个人贡献与验证

## 协作方式

本项目由候选人使用 Codex 辅助完成。候选人提供完整考试要求，选择第 1 题，首轮要求“暂时只跑离线 Mock，保留真实模型入口”，随后要求补充真实模型证据、贡献记录以及 GitHub 交付，并授权使用本人账号创建公开仓库。

AI 参与了需求拆解、Python 代码、合成数据、Mock 策略、真实模型适配器、测试、CLI、文档初稿和本地验证命令执行。当前版本的大部分实现与文字由 AI 生成，不能将其描述为候选人独立手写。

开发辅助 AI 与项目运行模型是两个不同层次：Codex 生成和修改工程代码；首轮工程验证使用 MockProvider，最终另接入千问 qwen-plus，实际执行完整矩阵并保存模型响应凭据。开发过程使用 AI 与项目真实模型运行分别记录。

## 个人贡献与协作记录

候选人实际承担了需求提供、验收约束传达、选题确认、先离线后真实验证的范围决策、公开仓库发布决策，并完成 GitHub 设备授权、选择千问和提供模型访问凭据。具体实现与自动验证由候选人委托 AI 执行。没有已确认的候选人直接编码或手工复跑记录，因此不将 AI 生成或自动执行归为个人独立编码与手工执行。

## 实际验证

AI 在本地执行了 demo 和可执行测试，保存原始输出、Trace 及测试日志。证据见 [03-evaluation.md](03-evaluation.md)。此类自动执行结果应由候选人亲自复现和解释，尤其是确认权限、幂等指纹、事务约束以及 Mock 与模型决策的边界。

OpenAI Docs 技能用于核对通用工具协议，并进一步读取服务商官方接口资料。最终真实模型经阿里云百炼调用；首轮 11/13，改进后完整矩阵 13/13，原始失败保留。GitHub 技能用于检查连接与发布条件；连接器失败后，使用本地 Git 和便携 GitHub CLI。没有使用多 Agent。

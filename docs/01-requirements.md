# 01 需求、范围与成功标准

## 用户与目标

用户是内容运营人员，需要把素材审核与排期结果整理成可检查、可确认的草稿。输入为素材 ID、渠道、要求时段、可搜索窗口及可选用户确认；素材元数据、审核规则和已有排期来自本地合成文件。

每个素材必须输出审核状态、风险或缺口、原要求时段、建议时段、待确认项、实际保存状态、任务状态及 `published=false`。

## 范围与约束

- 只保存草稿，不存在真实发布接口。
- 一小时一个时段，按渠道隔离；仅支持显式 `+08:00` 的整点时间。每请求 1..20 个不同素材，查询窗口最长 48 小时，结束时间包含在查询范围内。
- 原始时段须位于搜索窗口内。窗口是用户允许系统搜索和提出建议的范围，不自动表示用户同意改动硬性时段。
- `hard_time=true` 为默认：原时段不可用时可以建议并保存待确认草稿；未经明确同意不能将改期标记为确认。
- `hard_time=false` 表示用户授权在该窗口内直接调整，仍须检查风险和冲突。
- 确认来源仅为用户输入 `confirmed_slots`。模型不能修改请求，也没有可写的 `confirmed` 工具参数。用户确认时段不可用时，返回无可行时段并请求重新确认。
- 审核未通过、缺少必填元数据、未观察到时段可用时，不允许保存。
- 同一 `request_id + material_id` 幂等。原始请求变化需要新 ID；相同建议时段可由待确认更新为明确确认，不新增草稿。
- 待确认草稿也占用建议时段，避免两个草稿互相冲突。没有草稿取消/过期功能，试验之间可使用独立数据库。
- 整个请求具有共享执行步数上限，达到后返回 `incomplete`；之前成功保存的草稿仍如实报告。

## 六项必验收标准

| 验收点 | 成功标准 | 对应证据 |
|---|---|---|
| 正常排期 | 读取、审核、查询后保存一份草稿，状态与数据库一致 | `examples/mock/normal/` |
| 素材信息缺失 | 选择补查，仍缺则列出缺口；不保存 | `examples/mock/missing/` |
| 规则风险 | 返回命中的规则 ID 与原因，阻断保存 | `examples/mock/risk/` |
| 时段冲突 | 根据可用性提出替代时段，硬性改期标记待确认 | `examples/mock/conflict/` |
| 重复提交 | 两次执行返回同一 draft_id，数据库只有一份 | `examples/mock/duplicate/` |
| 保存失败 | 返回 failed，无伪造成功草稿，保留失败返回 | `examples/mock/save_failure/` |

额外覆盖：补查成功、查询错误恢复、无可用时段、用户确认、批量冲突、执行上限，以及更改占用时段后的行为变化。以上为离线流程成功标准，真实模型决策能力需单独验证。

## 非目标

本轮未实现界面、线上部署、多人身份认证、真实内容理解审核、真实平台发布或生产级 Runtime。规则依赖合成标签与版权元数据，不声称能识别视频画面本身的违规内容。
